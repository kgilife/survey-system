# 02｜帳號、權限與資料結構

## 1. 管理員驗證

- 登入使用 `email`／登入名稱與 `password`。
- 成功後建立短期 session token；前端存於 `sessionStorage`。
- 登入失敗受速率限制。
- 一般帳號可由 Email 收到 15 分鐘有效、只能使用一次的重設連結。
- 特殊帳號 `kgi` 使用登入名稱而非可收信 Email，因此不支援寄信重設。
- 登入狀態下可開啟個人資料頁面（`#/profile`）修改顯示名稱（`admin_name`）、`email` 或變更登入密碼；系統管理者特殊帳號 `kgi` 限制不可修改 Email 名稱。

> 現況限制：管理員 `password` 依既有業務決策以明文保存在受限主資料表。Google Sheet 與備份權限必須嚴格控管；後續宜另案改為不可逆雜湊。

## 2. 填寫者驗證

- 依據專案的 `access_mode` 設定分為兩種模式：
  - **指定使用者 (`specified`)**：使用專案名單中的帳號密碼（預設為員工代碼/生日四碼，密碼以 SHA-256 雜湊儲存）登入。
  - **開放所有人填寫 (`public`)**：免登入直接進入。系統自動產生 `guest_` 前綴的 UUID (例如 `guest_7d82b3a9...`)，作為匿名帳號綁定該裝置。
- 登入成功後建立短期 session token；前端存於 `sessionStorage` (指定使用者) 或綁定 `localStorage` (訪客接續)。
- 免登入訪客的資料在「暫存」或「送出」時，會自動匯入 `問卷使用者設定` 成為正式紀錄，確保相容既有圖表與下載功能。

## 3. 「管理員設定」現行欄位

| 欄位 | 用途 |
|---|---|
| `admin_id` | 管理員唯一識別碼 |
| `admin_name` | 顯示名稱 |
| `admin_folder_id` | 管理員 Drive 根資料夾 ID |
| `status` | 帳號狀態 |
| `created_at` | 建立時間 |
| `last_login_at` | 最近登入時間 |
| `email` | Email 或特殊登入名稱 |
| `password` | 現行登入密碼 |
| `role` | `system_admin` 或 `user` |
| `email_verified` | Email 驗證狀態 |
| `updated_at` | 最近更新時間 |

`admin_key_hash` 已停止使用並由遷移程序刪除，不得再新增或依賴。

## 6. 授權規則

- 所有管理 API 均須驗證管理員 token。
- 涉及專案的管理 API 還須確認 `專案索引.admin_id` 等於目前管理員。
- 填寫 API 須驗證填寫者 token、專案 ID 與帳號。
- 前端傳入的題目、選項、庫存與回答不得直接信任；後端必須依 schema 再驗證。
- Google Drive 題目圖片可設為知道連結者可檢視；使用者附件仍透過授權 API 下載。
