# 06｜非功能需求、部署與驗收

## 1. 可用性

- 手機與桌面瀏覽器均可操作。
- 非同步操作超過可感知時間時顯示進行中狀態。
- 上傳、登入、儲存、匯出等按鈕處理中須防止重複提交。
- 錯誤訊息須指出可採取的下一步，不只顯示技術代碼。
- 短條款、空庫存、空資料等邊界情況必須可理解且可完成。

## 2. 效能

- Apps Script 應減少逐格與重複 Spreadsheet RPC。
- 批次資料採一次讀取、記憶體處理與批次寫入。
- `master_()` 與 `projectDb_()` 僅開啟資料庫，不得在日常 API 請求掃描、建立或格式化所有工作表。
- 資料表建立與欄位升級採版本化 migration，只在初始化、部署升級或管理員修復時執行。
- 同一 API 請求須共用已開啟的 Spreadsheet 物件，操作紀錄不得為了寫入而重複開啟相同資料庫。
- 圖片限制 5 MB，顯示使用適當縮圖，避免原圖拖慢頁面。

## 3. 安全

- 全程 HTTPS。
- token 不寫入網址；管理員與填寫者 session 分離。
- API 執行身分、專案所有權、輸入格式與檔案內容都由後端驗證。
- 登入具速率限制，密碼重設 token 只存雜湊、限時且一次性。
- Google Sheet、Apps Script、Drive 與 GitHub 權限採最小權限。

## 4. 部署

- 前端推送至 GitHub `master` 後，由 GitHub Actions 建置並部署 Pages。
- 建置指令：`npm run build`；同時產生 `404.html` 支援靜態站路由。
- 後端以 clasp 推送至既有 Apps Script 專案，更新既有 Web App deployment，避免 API URL 改變。
- `VITE_GAS_API_URL` 或前端預設 endpoint 必須指向正式 Apps Script `/exec`。

## 5. 發布前驗收

- `npm run lint` 無新增錯誤。
- `npm test` 全數通過。
- `npm run build` 成功。
- 根網址直接顯示登入頁。
- 管理員登入、專案載入、問卷預覽與填寫者登入可用。
- 每種圖片上傳均顯示狀態且不會重複送出。
- 新舊 Drive 題目圖片皆能顯示。
- 數字設定可清空重輸入，失焦空白才恢復預設。
- Excel 巢狀路徑貼上後能逐層正確篩選。
- 短條款可直接勾選，長條款須捲到底。
- 庫存扣除、歸還、手動調整及紀錄正確。
- 問卷設計器依區段顯示題目，題目可在區段內及跨區段拖曳，區段可連同題目排序。
- 上一步、下一步、`Ctrl/Command + Z` 與重做快捷鍵可用，復原後的內容能正確自動儲存。
- 連續快速修改與復原時，較舊的儲存請求不會覆蓋最新畫面內容。
- 管理員及填寫者登入不得觸發全資料庫結構掃描；資料表升級以 `migrateSystem()` 單次執行。

## 6. 備份與復原

- Google Sheet 與 Drive 為主要資料資產，應依組織政策定期備份。
- 刪除專案移至垃圾桶前須二次確認完整專案名稱。
- 程式碼以 Git 保存版本；正式部署應能對應 Git commit 與 Apps Script deployment 版本。
